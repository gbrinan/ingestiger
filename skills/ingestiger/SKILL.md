원본 뭉치를 역추적 가능한 코퍼스로 바꾼다: 변환 → 로컬 정본 → (지시 시) 미러 → 적재 → 검증.

## Goal

원본 데이터를 **AI가 검색할 수 있는 코퍼스**로 만든다. 그것이 유일한 임무다.

**검색된다는 것은 값이 맞다는 증거가 아니다.** 열이 밀린 값도, 날짜가 숫자로 남은 값도
똑같이 색인되고 똑같이 검색된다. 그래서 진척은 적재 건수가 아니라
**원본까지 되짚을 수 있는 값의 수**다.

배치의 정산 버킷: **발견 = 적재 + 실패 + 건너뜀.**

- **발견** = 이번 배치가 집은 파일 수(≤50). 소스에 더 남았으면 정산에 섞지 말고
  "다음 배치"로 보고한다.
- **적재** = 로컬 정본 저장 **그리고** 코퍼스 적재까지 성공한 문서. 로컬 저장 후
  코퍼스 적재에 실패하면 실패 버킷이다(로컬 파일은 남긴다 — 다음 배치의 재시도 대상).
- **실패** = 변환·적재 실패, 그리고 3회 격리된 단위(사유 `격리`를 붙여 센다).
- **건너뜀** = 민감 판정·고객사 자료 등 의도적 제외 (경로와 사유만 보고).

미러는 별도 버킷(성공/실패)으로 따로 센다 — 미러 실패는 적재 실패가 아니다
(로컬 정본은 이미 존재한다).

## 저장 계층

로컬이 항상 정본(1차)이고, 미러(2차)는 지시가 있을 때만 만든다. 어느 미러가 실패해도
로컬 정본은 남는다.

| 층 | 조건 | 위치 |
|---|---|---|
| **로컬 (정본, 항상)** | 무조건 | 도구 설정이 정하는 코퍼스 기준 폴더 아래 `ingestiger/` — 경로를 직접 지어내지 않는다. 기준 폴더 설정이 없으면 호출자에게 묻는다 |
| **구글 드라이브 (미러)** | 지시에 공유·백업 의도가 있을 때 | 지시받은 드라이브 폴더에 로컬 정본 폴더 구조 그대로 |
| **선택 DB (미러)** | 지시에 DB 적재 의도가 있을 때 | 지시받은 DB의 코퍼스 스키마. 스키마 정의 파일이 유일한 기준이며, **스키마를 만들거나 바꾸지 않는다** — 없거나 다르면 멈추고 올린다 |

로컬 정본 폴더 구조 — 사람이 폴더만 열어도 무엇이 들어왔는지 보여야 한다:

```
<기준 폴더>/ingestiger/
├── index.md          # 위키형 색인: 문서당 1행 (제목 · 원본 경로 · content_hash · 적재일 · 적재처 · 상태)
├── updates.md        # 배치별 갱신 로그 (배치 id = <날짜>-<소스 약칭> · 정산 · 실패 목록)
├── md/<문서id>.md    # 변환된 마크다운
└── meta/<문서id>.json # 출처 경로·날짜·원본 확장자·변환 도구·확실도·content_hash 메타
```

- **문서id** = 원본 파일명(확장자 제외) + `-` + **원본 파일** sha256 앞 8자.
- **content_hash** = 변환 후 마크다운의 sha256 (index.md·meta의 해시 열은 이것).
- **상태** 열은 `적재 | 실패 | 건너뜀` — 실패·건너뜀도 행을 얻는다. 색인은 배치의
  전체 기록이지 성공 목록이 아니다.
- md·txt·csv처럼 변환 없는 포맷도 내용 그대로 `md/<문서id>.md`로 저장하고,
  원본 확장자는 meta에 기록한다.

## Workflow (배치당 최대 50개 파일)

1. **수집** — 지시받은 소스만 나열한다. 지시 없는 폴더는 열지 않는다.
   이때 센 수가 정산의 "발견"이다.
2. **변환** — 아래 라우팅 표대로 마크다운화한다. 이미 텍스트·마크다운(md, txt, csv)이면
   변환 없이 그대로 쓴다. 변환 결과가 이상하면(열 밀림, 날짜가 다섯 자리 정수, 표 붕괴,
   `#REF!`) 그대로 쓰지 말고 실패 버킷에 올린다.
3. **로컬 저장 (정본)** — `md/`와 `meta/`에 쓴다. `index.md` 행은 배치 종료 시
   문서마다 최종 상태와 함께 1행씩 추가한다.
4. **미러 (지시 시)** — 구글 드라이브 또는 선택 DB로 로컬 정본을 복사한다.
   DB 미러의 청킹은 5단계와 같은 규칙. 미러 결과는 별도 버킷으로 센다.
5. **적재** — 코퍼스/RAG 저장소에 넣는다. 저장소는 호출 환경의 도구 배선이 정한다 —
   후보가 없거나 여럿이면 지어내지 말고 호출자에게 묻는다. 청크는 문단 단위 500~1000자.
   문서마다 출처 경로·날짜 메타를 함께 남기고, 개념·관계가 뚜렷한 문서는
   구조(노드·엣지)를 보강한다.
6. **검증** — 적재된 값 3건을 골라 원본 좌표까지 되짚는다. 좌표는 `<파일>:<위치>` 꼴,
   위치는 포맷에 맞게 — 표는 `<시트>:<행>`, 문서는 페이지·절, 음성은 `mm:ss`.
   검색 저장소에 실제 질의를 던져 방금 넣은 문서가 나오는지 확인한다.
7. **보고** — `updates.md`에 배치 로그를 남기고, 출력 형식대로 보고한다.

### 변환 라우팅 (현재 도구 — 바뀌면 이 표만 고치면 된다. 루프는 그대로다)

| 포맷 | 도구 | 비고 |
|---|---|---|
| pdf, doc/docx, pptx, xlsx | docling | 표·레이아웃 보존. 스캔·저품질 PDF는 opendataloader-pdf로 보조 |
| hwp, hwpx | kordoc (CLI/MCP) | 한국 오피스 문서 전용 경로 |
| png (이미지 속 글자) | docling + OCR(`kor`) | 읽어낸 값에는 근거·확실도를 남긴다 |
| wav | faster-whisper (`language="ko"`) | 오프라인 STT. 전사문 머리에 원본 파일·길이 기록 |
| md, txt, csv | (변환 없음) | csv는 열 수·행 수를 meta에 기록 |
| 적재·검증 | 코퍼스 저장소의 ingest·query 도구 | 도구 목록의 정본은 이 표가 아니라 서버다 — 실제 목록을 조회해 확인한다 |

## Rules

이 스킬은 홀로 설치돼도 돌아가야 하므로 아래에 게이트 요지를 담는다.
**작업 환경에 `config/guides/corpus-gates.md`가 존재하면 그 원문이 우선한다**
(그 파일의 존재가 soloforce 계열이라는 판별 기준이다) — 첫 작업 전에 읽고,
이 절과 다르면 그쪽을 따른다.

- **원본은 읽기 전용.** 수정·이동·삭제하지 않는다. 산출물은 변환의 결과다.
- **지어내지 않는다.** 변환·읽기에 실패한 파일은 실패 목록에 그대로 올린다.
  조용히 빠진 파일이 가장 위험하다 — 정산이 안 맞으면 미완이다.
- **미상은 `미상`으로.** 읽지 못한 값은 공백도 추측도 아닌 `미상`으로 기록한다.
- **근거·확실도.** 이미지·음성처럼 판독으로 읽은 값에는 어디서 읽었는지(근거)와
  확인/추정(확실도)을 함께 남긴다.
- **3회 격리.** 3회 시도해도 통과 못 하는 단위는 붙잡지 말고 다음으로 간다.
  격리 = 실패 버킷에 사유 `격리`로 세고, 실패 목록에 경로를 남겨 호출자에게 올리는 것.
- **민감 판정.** "이게 의도치 않은 사람에게 보이면 누가 손해를 보나" — 답이 나오면
  그 문서·값은 건너뛰고 **경로만** 보고한다. 내용은 어느 저장 계층에도 옮기지 않는다.
- **고객사(제3자) 자료는 어느 적재처에도 넣지 않는다.** 코퍼스가 단일 테넌트 공유
  저장소라면 넣는 순간 사후 격리가 불가능하다. 판별은 지시·폴더명·문서 내용으로
  제3자 소유가 드러나는지로 하고, 애매하면 넣지 말고 묻는다. 섞여 들어오면 건너뛰고
  경로만 보고한다.
- **게이트를 약화시키지 않는다.** 통과시키려고 검사를 느슨하게 바꾸는 것은 미통과를
  완료로 보고하는 것과 같다.
- **스키마·색인 구조를 마음대로 만들거나 바꾸지 않는다.** 없거나 다르면 멈추고 올린다.
- **지시 없는 폴더는 열지 않는다.** 배치 상한 50을 넘기지 않는다.
- 예시는 항상 일반형(`<파일>:<시트>:<행>`)으로 남긴다 — 실제 값은 보고서에만.

## Verification

배치를 끝내기 전에 확인한다:

1. **정산 일치**: 발견 = 적재 + 실패 + 건너뜀 (버킷 정의는 Goal 절). 미러 버킷도 합이 맞는다.
2. **역추적 3건**: 적재된 값 3건이 원본 좌표까지 되짚어지고 그 좌표가 보고에 있다.
3. **색인 정합**: `index.md` 행 수 증가분 = 발견 수 (상태 열 합계가 정산과 일치).
   `updates.md`에 배치 로그 존재.
4. **검색 확인**: 방금 적재한 문서가 실제 질의로 검색된다 — 단, 이것은 존재 확인이지
   값이 맞다는 증거가 아니다(그 증거는 2번이다).
5. **미러 확인 (미러했다면)**: 드라이브 미러는 파일 수·content_hash가 로컬 정본과
   일치. DB 미러는 문서 수와 문서별 content_hash 메타가 일치 (청크 수는 저장소 몫).

### 출력 형식 (보고)

```
[코퍼스 배치] <소스>
정산: 발견 N · 적재 N · 실패 N · 건너뜀 N  (합 일치)
미러: <없음 | 드라이브 성공 N/N | DB 성공 N/N>
역추적: <값> ← <파일>:<위치>  (3건)
다음 배치: <남은 소스 | 격리 건 재시도 | 없음>
```
